# Releasing

Releases are cut from tags and built by the
[`release.yml`](../.github/workflows/release.yml) workflow. Every published
artifact comes with SLSA v1 build provenance generated by GitHub, so consumers
can verify that a file was built from this repository by this workflow rather
than supplied by a third party.

## Release artifacts

Each release publishes:

| File | Description |
| --- | --- |
| `task_escrow.wasm` | Deployable `task-escrow` Soroban contract (`wasm32v1-none`). |
| `bridge-node` | Runtime binary that wires the ROS 2 transport to settlement. |
| `stellar-testnet-smoke` | Manual end-to-end testnet smoke binary. |
| `simulated-robot` | Simulated robot-side demo binary. |
| `SHA256SUMS` | SHA-256 checksums for the files above. |
| `*.sigstore.json` (attestation) | Stored by GitHub with the repository; not a release asset. |

The binaries are Linux x86_64 builds produced on `ubuntu-latest`. Builds are
not yet cross-compiled for other platforms.

## Cut a release

1. Update `CHANGELOG.md` and the workspace version if needed.
2. Commit the changes and merge them to `main`.
3. Create and push an annotated tag:

   ```bash
   git checkout main
   git pull --ff-only
   git tag -a v0.2.0 -m "v0.2.0"
   git push origin v0.2.0
   ```

4. The `Release` workflow builds, attests, and publishes the artifacts. Check
   the **Actions** tab and the resulting GitHub release.

### Test a release without shipping a version

Use a pre-release tag and make sure it does not point at untagged local work:

```bash
git tag -a v0.2.0-rc.1 -m "v0.2.0-rc.1"
git push origin v0.2.0-rc.1
```

You can also re-run the workflow from **Actions → Release → Run workflow** and
pass the existing tag in the `tag` input. Re-running republishes the same
artifacts and a fresh attestation for that digest.

## Verify a release

Install the [GitHub CLI](https://cli.github.com/) (2.49 or newer) and download
the release assets, for example:

```bash
gh release download v0.2.0 --repo Primex-tech-labs/stellar-ros-bridge --dir dist
```

### 1. Check the checksums

```bash
cd dist
sha256sum -c SHA256SUMS
```

### 2. Verify the SLSA provenance

Each file in `SHA256SUMS` is covered by a GitHub attestation. Verify that the
artifact was built by this repository's release workflow:

```bash
for file in task_escrow.wasm bridge-node stellar-testnet-smoke simulated-robot; do
  gh attestation verify "${file}" \
    --repo Primex-tech-labs/stellar-ros-bridge
done
```

A successful verification prints the workflow, commit SHA and build platform.
`gh attestation verify` fails if the file was modified after the build, was
built from another repository or branch, or has no attestation.

To inspect the raw provenance instead of only checking it:

```bash
gh attestation verify task_escrow.wasm \
  --repo Primex-tech-labs/stellar-ros-bridge \
  --format json
```

### 3. Confirm the commit

The verification output includes the source commit. Check that it is the
commit you intended to release:

```bash
gh release view v0.2.0 --repo Primex-tech-labs/stellar-ros-bridge --json targetCommitish
```

## Deploying the verified contract

After verifying `task_escrow.wasm`, deploy it with `stellar-cli`:

```bash
stellar contract upload \
  --wasm dist/task_escrow.wasm \
  --network testnet \
  --source <funded-identity>

stellar contract deploy \
  --wasm-hash <uploaded-wasm-hash> \
  --network testnet \
  --source <funded-identity>
```

Record the wasm hash and deploy transaction in `CHANGELOG.md`, as done for
previous testnet deployments.

## Troubleshooting

- **`gh attestation verify` reports "no attestations"**: the release predates
  the provenance workflow, or the file was downloaded from somewhere other than
  the release assets.
- **`sha256sum -c` fails**: the download is incomplete or has been modified;
  delete it and download again.
- **The release job cannot create a release**: confirm the tag exists and that
  the workflow has `contents: write` permission (the default in this
  workflow). For a `workflow_dispatch` run, the `tag` input must match an
  existing tag.
